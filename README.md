# stabar

Status bar, Windows 系统状态小组件。
**无标题条、无背景、置顶**，支持几乎完全透明地贴在屏幕上,
已实现磁盘占用逼近水位或鼠标悬停时才亮起来，支持自定义阈值。

- 显示:每个**已加载盘符**一行(占用进度条与百分比,颜色随阈值变蓝 / 黄 / 红),默认含移动硬盘;
  盘符不写死,插上/拔下之后跟着变(见配置里的 `drives`)
- 交互:左键拖动、鼠标悬停提亮、右键菜单刷新与退出
- 托盘:小组件可以调到几乎看不见,所以托盘图标是唯一稳定的入口

## 运行

需要 Windows 11 与 Python 3.13(依赖由 uv 管理)。

```powershell
uv run python main.py
```

## 操作

| 操作 | 效果 |
|---|---|
| 左键拖动小组件 | 移动位置,自动记住 |
| 鼠标悬停 | 立即提亮到 100%,并显示各盘详情(约 700 ms 后弹出;整块区域都可) |
| 右键小组件 | 隐藏 / 立即刷新 / 退出 |
| 左键单击托盘图标 | 显示 / 隐藏小组件 |
| 再次启动 stabar | 不会开出第二份:已有实例的小组件被叫出来,新进程自己退出(单实例按**配置目录**分域;`STABAR_ALLOW_MULTIPLE=1` 可故意开多份) |
| 右键托盘图标 | 版本号、配置和日志目录、鼠标穿透、开机自启、贴边隐藏、还原配置、刷新频率、橙色阈值、红色阈值、常亮阈值、调整尺寸、透明度、显示/隐藏、立即刷新、退出(**每一项都有悬停提示**) |
| 托盘 → 贴边隐藏 | **默认开**。把小组件拖到屏幕边(8px 内)就吸附齐平;**压出屏幕也算贴边**(拖出去一半松手会被拉回边上摆正),鼠标移开就折叠成贴着边的一条**断线**:一个盘一段、段间断开、每段等长(**与屏幕边平行** —— 贴左右是竖的、贴上下是横的),颜色随阈值变蓝 / 橙 / 红;大小固定,不随「调整尺寸」变。蹭到它就长回原样。开启鼠标穿透时会自动关掉它(穿透后收不到任何鼠标) |
| 托盘 → 调整尺寸 | 滑杆调小组件**整体大小**(60% ~ 200%,一格 1%),拖动实时预览、松手落盘,下次启动恢复 |
| 托盘 → 刷新频率 | 步进器调"每几秒读一次盘"(1 ~ 60 秒、步进 1、可直接敲数字),立刻生效、菜单关闭时落盘 |
| 托盘 → 橙色 / 红色阈值 | 步进器按百分比设两条**颜色**线(步进 1%),立刻生效、菜单关闭时落盘;橙色必须比红色至少低 1% |
| 托盘 → 常亮阈值 | 步进器设"界面常亮"的占用线(步进 1%);占用 ≥ 它**或** ≥ 红色阈值都会常亮 —— 即取两者中更低的那条 |
| 托盘 → 透明度 | 滑杆调"未报警时"的前景不透明度(5% ~ 100%,一格 5%),拖动实时预览、松手落盘 |
| 托盘 → 鼠标穿透 / 开机自启 | 行内右侧的**复选框**(不用菜单项的系统勾选,菜单因此窄 21px);穿透开启后窗口不再接收鼠标 |
| 托盘 → 版本号 | 最上面一行:右边显示当前版本(唯一来源是 `pyproject.toml`);悬停只讲版本,不夹带路径 |
| 托盘 → 配置和日志目录 | 右侧「打开」按钮:用系统默认程序打开配置与日志所在目录(提示里就写着完整路径);打包后是 `%LOCALAPPDATA%\stabar`,源码运行是项目目录 |
| 托盘 → 还原配置 | 右侧「还原」按钮:弹确认框逐行列出与默认值**不同**的项(当前值 → 默认值),确认后立刻恢复并落盘;**窗口位置不在其中**;本来就都是默认值时会说明一句,不会点了没反应 |
| 悬停托盘图标 | 显示各盘的**占用百分比**(一行:托盘提示受 Windows 限制只有 128 个字符,放不下完整明细;完整明细悬停小组件) |

开启"鼠标穿透"后窗口不再接收鼠标事件,只能从托盘菜单关掉。

**开机自启**勾选后写入当前用户的注册表 Run 键(`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`,值名 `stabar`),只影响当前用户、不需要管理员权限,并且能在 **任务管理器 → 启动** 里看到和关闭。注册的是"当前运行方式的路径"—— 打包后就是 exe 自身,
开发时是 `pythonw.exe main.py` —— 所以挪动目录后自启会失效,重新勾选一次即可。

## 配置

配置是 INI 文件,启动时读取,并把生效的不透明度回写进去:

| 运行方式 | 位置 |
|---|---|
| 源码运行 | 项目目录下的 `stabar.ini` |
| 打包运行 | `%LOCALAPPDATA%\stabar\stabar.ini` |

两份是**独立**的,改一份不影响另一份。

| 键 | 含义 |
|---|---|
| `pos_x` / `pos_y` | 窗口位置,拖动后自动写入 |
| `idle_opacity` | 平时前景不透明度。最低 `0.05`(5%),也就是托盘滑杆的最后一格 |
| `refresh_seconds` | 刷新间隔(秒)。允许 `1` ~ `60`,默认 `15`,也可从托盘菜单的步进器改 |
| `warn_threshold` | 橙色警戒线(**只影响颜色**)。默认 `0.85`,托盘菜单按 `85%` 显示 |
| `danger_threshold` | 红色危险线。默认 `0.90`,必须比橙色至少高 `0.01` |
| `lit_threshold` | 常亮阈值。默认 `0.90`(与红色相同);占用 ≥ 它或 ≥ 红色都会让界面常亮 |
| `edge_hide` | 贴边隐藏。默认 `true`(贴到边就收起成小尾巴);`false` 就是普通的悬浮窗 |
| `ui_scale` | 整窗缩放系数(`0.6` ~ `2.0`),托盘「调整尺寸」滑杆改它 |
| `drives` | 要显示哪些盘。默认 `auto`(所有已加载盘符:固定盘 + 可移动盘,含移动硬盘);写 `C,E` 就只显示这两个。空光驱、无卡读卡器、映射的网络盘不会出现 |
| `show_all_drives` | 显示所有磁盘盘符。默认 `true`;`false` 时探测只收本地固定盘,U 盘 / 读卡器这类可移动盘不再出现(USB 硬盘盒报固定盘类型,仍会显示)。托盘菜单「鼠标穿透」上方那个勾选;ini 里手写 `drives` 白名单也受它约束 |

注意两点:`QSettings` 重写文件时**不保留注释**,别在 ini 里写说明;回写之后 ini 成为
权威值,想回到代码里的初值就把 `idle_opacity` 那一行删掉。

其余参数(刷新间隔、提亮水位、警告线)在 `main.py` 顶部的"观感调节区"里;
窗口与贴边的**尺寸常量**与各项**量程**在 `layout.py`,界面**配色**在 `diskbar.py`,
菜单常量在 `tray.py` —— 都与用它们的代码放在一起。

## 日志

开发时 INFO、打包后 WARNING,用环境变量覆盖:

```powershell
$env:STABAR_LOG_LEVEL = "DEBUG"    # 排查用;大小写不敏感,重启进程才生效
```

**日志只有两份**:

| 运行形态 | 位置 |
|---|---|
| 打包运行 | `%LOCALAPPDATA%\stabar\stabar.log` |
| 其他(源码运行、跑测试) | 项目目录下的 `stabar.log` |

逐条 flush;超过约 1 MB 就**清空重写**,不产生历史文件(旧内容会丢,要留档就把
`logging_setup.LOG_MAX_BYTES` 调大)。`STABAR_CONFIG_DIR` 只隔离配置,不会移动日志。事件行统一为
`event=<名词> key=value ...`,一行一个事件,既给人看也当自动化测试的观察点。完整的事件
清单、位置对照和测试用法见 [`日志使用说明.md`](日志使用说明.md)。

实现在 `logging_setup.py`(从 `main.py` 拆出),日志相关改动只改那一个文件。

打包成 `--noconsole` 后 `sys.stderr` 是 `None`,所以**不要用 `print(..., file=sys.stderr)`
报错信息 —— 它会静默消失**,要写成日志。

## 测试

**1. 单元测试(默认,含进程内 A 层 E2E)** —— 离屏 Qt,不弹真窗口、不碰真实 `stabar.ini` 与真实注册表:

```powershell
uv run pytest -q
```

**2. 源码形态 E2E** —— 进程外真输入(会真的移动鼠标、抢焦点,必须有真实桌面会话),**不必打包**:

```powershell
$env:STABAR_E2E = "1"; $env:STABAR_E2E_TARGET = "dev"; uv run pytest tests/test_e2e_real_input.py -q
```

**3. 打包形态 E2E** —— 只有要验证**打包形态自身**时才跑;不设 `STABAR_E2E_TARGET` 时它本来就是默认目标:

```powershell
uv run pyinstaller --noconfirm --clean stabar.spec
$env:STABAR_E2E = "1"; uv run pytest tests/test_e2e_real_input.py -q
```

三点说明:

- **skip 原因(`-rs`)与最慢 4 条(`--durations=4`)由 `pyproject.toml` 的 `addopts` 默认带上**,不用敲:skip 都有"为什么"要交代;真机 E2E"哪一步停留很久"靠后者定位;
- 新增用例该写在哪一层(纯函数 / 组件 / 进程内 E2E / 进程外真输入 E2E)见
  [`AGENTS.md`](AGENTS.md) 的「测试分层」;
- 多条环境变量之间用 **`;` 而不是 `&&`**:`&&` 右边必须是 pipeline,而赋值不是 —— 实测直接
  `ParserError`(见 `AGENTS.md` 的「代码检查与格式化」);
- 开关留在**当前会话**里(想清掉:`Remove-Item Env:STABAR_E2E`);没打包就跑第 3 种会整份 skip,不是失败。

两个设计上的注意:选菜单项按**名称**定位(UI Automation),与菜单顺序无关;检测到你在用鼠标时会重试、
再整体跳过,**不会记成失败**。

## 打包

```powershell
uv run python .\scripts\make-icon.py          # 只有改了图标图案才需要重新生成
uv run pyinstaller --noconfirm --clean stabar.spec
```

产物在 `dist\stabar\`,**必须整目录分发**:`stabar.exe` 单独拷出去不能运行,要带上
`_internal`。

图标设计写在 `scripts\make-icon.py`,它生成的 `stabar.ico` 是**托盘与 exe 共用的唯一来源**:
托盘运行时读这个文件(`stabar.spec` 的 `datas` 会把它带进 `_internal`),exe 的文件图标
嵌的也是同一份。所以改了图案必须重新生成再重新打包。

裁剪逻辑都在 `stabar.spec` 里。PySide6 的官方钩子会把整个包目录的 DLL 都收进来,其中
Quick/Qml/Pdf/OpenGL/Svg、Mesa 软件 OpenGL 回退、Qt 翻译、图片格式、TLS 相关插件我们一个都
用不到,剔掉之后体积从 111.6 MB 降到 **55.2 MB**。唯一保留的"多余"模块是 QtNetwork —— 单实例
用它做本地命名管道唤醒(`single_instance.py`),只多带了它自己那一份;OpenSSL / TLS 仍然裁掉。

## 资源占用

| 指标 | 源码运行 | 打包(onedir) |
|---|---|---|
| 磁盘 | (.venv 675 MB) | 55.2 MB |
| 启动 → 窗口 | 1136 ms | 670 ~ 770 ms |
| 常驻工作集 | 66.0 MB | 57.1 MB(含托盘) |
| 私有内存 | 26.9 MB | 23.8 MB |
| 空闲 CPU | — | ≈ 0 |

空闲 CPU 几乎为零:每 15 秒一次的刷新里,读盘与数据处理本身不消耗 CPU,成本全在重绘
(约 1 ~ 1.6 ms/次)。测量方法、字段含义与逐项结论见 [`scripts/readme.md`](scripts/readme.md)。

## 改代码前先看这几条

- **不要用 `setWindowOpacity` 做前景淡化。** Windows 对分层窗口按像素 alpha 做鼠标命中
  测试,`setWindowOpacity` 会把整层相乘,连隐形底板一起压成 alpha 0,鼠标直接穿透到桌面
  —— 悬停提亮和拖动都会失效。所以前景是"直接画 alpha"。
- **`HIT_AREA_ALPHA = 1` 是功能代码,不是装饰。** 背景全透明后,窗口矩形里只有字形能接收
  鼠标;保留一层 alpha = 1 的隐形底板,整块区域才能拖动和悬停。别改成 0。
  同理,**贴边收起后的小尾巴必须整块留在屏幕内** —— 跑到屏幕外、又收不到鼠标,就再也蹭不回来了,
  所以收起是"把窗口折成贴边的一条小线段",别改成"滑出屏幕"。
- **亮度只有 0/1 两档,由「常亮阈值」和「红色阈值」决定**(取两者中更低的那条);橙色阈值**只改颜色**。
  以前用的是 `REVEAL_START → 警告线` 的渐亮斜坡,现已取消:斜坡让"平时隐身"变得不可预期,
  而且起点和警告线凑成一对,概念上像重复(见 `开发经验.md` 第 12 条)。
- **文字必须带暗色描边**,否则浅色壁纸下白字会消失。
- **不要用 `print(..., file=sys.stderr)` 报告问题**:打包成 `--noconsole` 后 `sys.stderr`
  是 `None`,打印会静默消失。要写日志(`log.warning("event=...")`),它一定落在文件里。
- **托盘是唯一稳定入口**:退出、隐藏、鼠标穿透都放在托盘菜单里,因为小组件可能被调到
  几乎看不见。

## 为什么是 Python + PySide6

需求很小(两个盘符 + 透明度 + 无边框),而 Qt 对无边框、逐像素透明、置顶窗口的支持是
一等公民,单文件 400 行就能写完。对比过的方案:WPF / WinUI 3 更重(70 ~ 130 MB);
Tauri 省的是体积不是内存(WebView2 子进程合计 80 MB 起);原生 Rust / C++ 能压到 10 MB,
但要自己实现分层窗口与文字描边。Nuitka 也试过 —— 它的优势是防反编译和纯 Python 计算
加速,对"Qt 巨库 + 每 15 秒读一次系统调用"的小组件没有收益。
